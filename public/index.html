1. ¿Qué hace esta API?

Esta API funciona como una capa intermedia entre una aplicación cliente y el Web Service de Factura Electrónica de ARCA, denominado WSFE.

La aplicación consumidora proporciona los datos del comprobante y las credenciales temporales obtenidas previamente mediante WSAA: token y sign.

La API utiliza esas credenciales para comunicarse con WSFE, consultar el número correspondiente y solicitar la autorización del comprobante.

Finalmente devuelve un JSON con el resultado de la operación.

Esta API no genera Token ni Sign. La aplicación consumidora debe encargarse de la autenticación ante WSAA.

2. ¿Cómo funciona?

1. La aplicación obtiene un certificado digital autorizado.
2. Utiliza WSAA para obtener un Ticket de Acceso.
3. WSAA devuelve Token y Sign.
4. La aplicación envía Token, Sign y los datos del comprobante a esta API.
5. La API consulta ante ARCA el último comprobante autorizado.
6. La API utiliza el siguiente número y envía la solicitud a WSFE.
7. ARCA responde con un CAE o con los errores correspondientes.
El consumidor no debe asumir el número de comprobante. El número utilizado debe ser el siguiente disponible informado por ARCA.

3. Requisitos previos

Requisito Descripción
Certificado digital Certificado autorizado para utilizar el Web Service correspondiente.
WSAA Acceso al servicio de autenticación de ARCA.
Token y Sign Credenciales temporales generadas mediante WSAA.
CUIT emisora CUIT de la entidad que emite los comprobantes.
Punto de venta Punto de venta habilitado para facturación electrónica.
La configuración del certificado, su autorización para el Web Service y el punto de venta se realizan fuera de esta API.

7. Solicitar CAE

POST /wsfe/solicitar-cae

Solicita a ARCA la autorización de una factura, nota de crédito o nota de débito.

La API obtiene internamente el siguiente número de comprobante disponible para el punto de venta y tipo de comprobante enviados.

Headers

Content-Type: application/json

X-Internal-Api-Key: eYDlzQXNWKOP7H24kp3aGovZ65drRMJCwunB8mLtUhjFxE1g

Campos del body

Campo Tipo Estado Descripción
invoiceId number requerido Identificador interno de la factura en el sistema consumidor. No es el número fiscal de ARCA.
reintentoAutomatico boolean opcional Indica si la solicitud pertenece a un reintento automático. El valor predeterminado es false.
token string requerido Token obtenido mediante WSAA.
sign string requerido Sign obtenido mediante WSAA.
cuit string requerido CUIT del emisor.
puntoVenta number requerido Punto de venta habilitado.
tipoComprobante number requerido Código ARCA/AFIP del comprobante.
concepto number requerido 1 = productos, 2 = servicios, 3 = productos y servicios.
docTipo number requerido Tipo de documento del receptor.
docNro string requerido Número del documento del receptor.
condicionIvaReceptorId number requerido Condición frente al IVA del receptor.
fecha string requerido Formato YYYYMMDD.
importeTotal number requerido Importe total del comprobante.
importeNeto number requerido Importe neto informado.
importeIva number opcional Importe de IVA cuando corresponda.
alicuotasIva array condicional Obligatorio cuando el tipo de comprobante discrimina IVA.
comprobantesAsociados array condicional Obligatorio en notas de crédito y notas de débito.
fchServDesde string condicional Inicio del servicio. YYYYMMDD. Obligatorio con concepto 2 o 3.
fchServHasta string condicional Fin del servicio. YYYYMMDD. Obligatorio con concepto 2 o 3.
fchVtoPago string condicional Vencimiento del pago. YYYYMMDD. Obligatorio con concepto 2 o 3.
monedaId string condicional Código de moneda para comprobantes que lo requieren.
monedaCotizacion number condicional Cotización de la moneda.
paisDestino number condicional País de destino para exportación.
permisosEmbarque array condicional Permisos de embarque para exportación, cuando correspondan.

invoiceId

Es un identificador proporcionado por el sistema que consume la API. Puede ser el ID de una factura de una base de datos, por ejemplo: 

"invoiceId": 316

No debe confundirse con numeroComprobante. El primero pertenece al sistema consumidor y el segundo es el número fiscal que ARCA asigna al comprobante.

reintentoAutomatico

Utilizar false o no enviar el campo para: 

"reintentoAutomatico": false

Utilizar true solamente cuando la petición provenga de un proceso automático de reintentos: 

"reintentoAutomatico": true

"puntoVenta": 1,
"tipoComprobante": 11,

}

Respuesta aprobada

HTTP/1.1 200 OK

{
"exito": true,
"cae": "86390928103236",
"caeVencimiento": "20261005",
"numeroComprobante": 2

Cuando exito es true, el comprobante fue aprobado y la respuesta incluye:

Campo Descripción
cae Código de autorización electrónico.

}

}
Un HTTP 200 indica que la API procesó la solicitud. Para saber si ARCA aprobó el comprobante hay que comprobar el valor de exito.

8. Reglas de importes según el tipo de comprobante

Los campos importeNeto, importeIva, importeTotal y alicuotasIva no se utilizan exactamente de la misma manera en todos los tipos de comprobante.

Es importante enviar estos valores de acuerdo con las reglas de WSFE. La API no debe recibir el mismo esquema de importes para A, B y C.

Factura A

La Factura A informa por separado el importe neto gravado y el IVA.

Campo Qué enviar
importeNeto Importe neto gravado antes del IVA.
importeIva Importe total de IVA.
alicuotasIva Detalle de las alícuotas que forman el IVA.
importeTotal Neto + IVA + otros componentes que correspondan.

Ejemplo con IVA del 21 %:

{
  "importeNeto": 1000,
  "importeIva": 210,
  "importeTotal": 1210,
  "alicuotasIva": [
    {
      "id": 5,
      "baseImp": 1000,
      "importe": 210
    }
  ]
}
La suma de los importes de alicuotasIva debe coincidir con importeIva.

Factura B

En WSFE, la Factura B también utiliza los campos de IVA. El IVA puede estar incluido en el precio que recibe el cliente, pero si corresponde informar IVA ante WSFE, la API debe recibir el neto, el IVA y el detalle de las alícuotas.

Campo Qué enviar
importeNeto Importe neto gravado.
importeIva Importe total de IVA.
alicuotasIva Detalle de las alícuotas correspondientes.
importeTotal Neto + IVA + otros componentes que correspondan.

Ejemplo con IVA del 21 %:

{
  "importeNeto": 1000,
  "importeIva": 210,
  "importeTotal": 1210,
  "alicuotasIva": [
    {
      "id": 5,
      "baseImp": 1000,
      "importe": 210
    }
  ]
}

Factura C

Factura C tiene una regla diferente. Para WSFE, el campo ImpIVA debe ser 0 y no debe informarse el detalle de IVA.

En esta API eso significa:

Campo Qué enviar
importeNeto Importe del subtotal de la operación.
importeIva Debe ser 0.
alicuotasIva No debe informarse.
importeTotal Debe coincidir con el subtotal cuando no existen otros tributos.

Ejemplo: 

{
  "importeNeto": 17654.63,
  "importeIva": 0,
  "importeTotal": 17654.63
}
No enviar una Factura C de esta forma: 
{
  "importeNeto": 14590.60,
  "importeIva": 0,
  "importeTotal": 17654.63
}

Ese request sería rechazado porque WSFE exige que, para una Factura C, el importe total coincida con la suma de ImpNeto + ImpTrib.

En particular, que el sistema consumidor tenga internamente un precio base más un cálculo propio del 21 % no significa que ese 21 % deba enviarse como IVA separado en WSFE para una Factura C.

Factura M

La Factura M utiliza IVA discriminado en WSFE de forma similar a los comprobantes que informan IVA.

Campo Qué enviar
importeNeto Importe neto gravado.
importeIva Importe total de IVA.
alicuotasIva Detalle de las alícuotas.
importeTotal Neto + IVA + otros componentes que correspondan.

Factura E

Los comprobantes E no se procesan mediante esta API. WSFEV1 de ARCA no es el Web Service correspondiente a los comprobantes de exportación.

Si se envía: 

"tipoComprobante": 19

la API devuelve: 

HTTP 400

{
  "exito": false,
  "errores": [
    {
      "codigo": "COMPROBANTE_NO_SOPORTADO",
      "mensaje": "Los comprobantes E no se procesan mediante WSFEV1. ARCA utiliza WSFEXV1 para comprobantes de exportación."
    }
  ]
}

Lo mismo se aplica a los tipos 20 y 21.

Resumen

Tipo importeNeto importeIva alicuotasIva importeTotal
A Neto gravado IVA Sí, cuando corresponde Neto + IVA + otros
B Neto gravado IVA Sí, cuando corresponde Neto + IVA + otros
C Subtotal 0 No Subtotal + otros
M Neto gravado IVA Sí, cuando corresponde Neto + IVA + otros
E No soportada por esta API. Requiere WSFEXV1.
La API valida la coherencia entre estos campos antes de solicitar la autorización a ARCA. Si los importes no son compatibles con el tipo de comprobante, la solicitud debe corregirse antes de volver a intentar la emisión.

9. Consultar próximo número

GET /wsfe/ultimo-comprobante

Consulta cuál será el próximo número de comprobante disponible para un determinado CUIT, punto de venta y tipo de comprobante.

Esta operación no emite ningún comprobante.

Headers

X-Internal-Api-Key: eYDlzQXNWKOP7H24kp3aGovZ65drRMJCwunB8mLtUhjFxE1g

Parámetros

Parámetro Tipo Descripción
token string Token de WSAA.
sign string Sign de WSAA.
cuit string CUIT emisora.
puntoVenta number Punto de venta.
tipoComprobante number Código de comprobante.

Ejemplo

GET /wsfe/ultimo-comprobante?token=TOKEN&sign=SIGN&cuit=20111111112&puntoVenta=1&tipoComprobante=11 HTTP/1.1

Host: api-arca-wsfe.onrender.com
X-Internal-Api-Key: eYDlzQXNWKOP7H24kp3aGovZ65drRMJCwunB8mLtUhjFxE1g

Respuesta

{

"exito": true,
"proximoNumero": 46
}
Si ARCA informa que el último comprobante autorizado es el 45, la API devuelve 46.

10. Emisión inicial y reintentos

La API distingue entre una emisión normal y los reintentos.

Situación reintentoAutomatico Rate limit
Emisión inicial false No
Reintento manual false No
Reintento automático true Sí

Rate limit automático

Cuando reintentoAutomatico es true, la API utiliza una clave compuesta por: 

CUIT + invoiceId

Por ejemplo: 

30-11111111111 + 235
30-22222222222 + 235
30-11111111111 + 236

Las tres combinaciones son independientes.

Configuración actual

RATE_LIMIT_MAX_REQUESTS=1
RATE_LIMIT_VENTANA_MS=480000

La ventana actual es de 8 minutos.

Esto permite que un sistema externo programe, por ejemplo, un reintento cada 10 minutos sin que pequeñas diferencias de tiempo provoquen un bloqueo inmediato.

HTTP 429

HTTP/1.1 429 Too Many Requests
Retry-After: 120

{
  "exito": false,
  "errores": [
    {
      "codigo": "RATE_LIMIT",
      "mensaje": "El reintento automático de esta factura fue limitado temporalmente"
    }
  ]
}

Retry-After expresa en segundos el tiempo restante estimado antes de que pueda realizarse otra solicitud automática para esa factura.

La API no decide cuándo debe volver a intentarse la factura. El scheduler o sistema consumidor es quien debe controlar ese proceso.

11. Respuestas HTTP

HTTP Significado Acción recomendada
200 La API procesó la solicitud. Comprobar el campo exito.
400 Request inválido o incompleto. Corregir los datos enviados.
401 API key ausente o incorrecta. Verificar X-Internal-Api-Key.
404 Endpoint inexistente. Verificar la URL.
408 Timeout. Puede considerarse un error transitorio.
429 Rate limit de reintento automático. Esperar el valor indicado por Retry-After.
500 Error interno. Registrar el error y evaluar reintento.

Regla importante

No se debe determinar el resultado únicamente por el código HTTP.

Para el endpoint de CAE: 

HTTP 200 + exito true
= comprobante aprobado

HTTP 200 + exito false
= ARCA rechazó el comprobante o no pudo aprobarlo

16. Errores

Errores propios de la API

Código HTTP Significado
VALIDACION 400 El body o los parámetros no cumplen el esquema esperado.
RATE_LIMIT 429 Se superó temporalmente el límite de reintentos automáticos para una combinación CUIT + invoiceId.
ERROR_INTERNO 500 Error interno, timeout o problema de comunicación.
NOT_FOUND 404 Endpoint inexistente.

Errores devueltos por ARCA

Los errores funcionales de ARCA aparecen dentro de errores. 

{
  "exito": false,
  "numeroComprobante": 235,
  "errores": [
    {
      "codigo": "10016",
      "mensaje": "CUIT representado no incluido en Token"
    }
  ]
}

El código y mensaje dependen de la validación realizada por ARCA.

17. Seguridad

API key

El acceso a los endpoints protegidos requiere la siguiente API key: 

eYDlzQXNWKOP7H24kp3aGovZ65drRMJCwunB8mLtUhjFxE1g

La clave se valida mediante el header X-Internal-Api-Key.

Token y Sign

Token y Sign deben obtenerse mediante WSAA. Deben mantenerse del lado servidor de la aplicación consumidora.

HTTPS

Las solicitudes deben realizarse mediante HTTPS.

Si la API key se cambia en el servidor, la documentación y los clientes que utilicen la API deberán actualizarse.

Reintento automático

Un proceso automático debe enviar: 

{
  "invoiceId": 316,
  "reintentoAutomatico": true
}

Los demás campos del comprobante también deben enviarse normalmente.

Reintento manual

Una aplicación que realiza una nueva solicitud por decisión del usuario debe enviar: 

{
  "invoiceId": 316,
  "reintentoAutomatico": false
}

Los reintentos manuales no consumen el límite destinado a reintentos automáticos.

19. Flujo completo recomendado

1. Obtener credenciales Token y Sign mediante WSAA.
2. Preparar los datos del comprobante.
3. Generar un invoiceId interno para identificar la operación.
4. Enviar POST a /wsfe/solicitar-cae.
5. Comprobar HTTP 200 y después comprobar el campo exito.
6. Si exito=true, guardar CAE, fecha de vencimiento y número de comprobante.
7. Si exito=false, analizar el contenido de errores.
8. Si el consumidor implementa reintentos automáticos, utilizar reintentoAutomatico=true y respetar Retry-After cuando exista una respuesta 429.
