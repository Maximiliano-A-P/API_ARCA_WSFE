🧾 API ARCA WSFE

API intermediaria para facturación electrónica AFIP/ARCA

● Servicio activo

¿Qué es esta API?

Se encarga de comunicarse con el servicio WSFE (Web Service de Facturación Electrónica) de ARCA para solicitar el CAE de un comprobante, consultar el próximo número disponible, y devolver todo en un formato JSON simple. No maneja el WSAA (autenticación/certificado) — eso lo resuelve la aplicación que consume esta API, que le pasa el Token y Sign ya generados en cada request.

Autenticación

Todas las rutas, salvo /health, exigen un header de autenticación. Sin él, o con un valor incorrecto, la API responde 401 Unauthorized antes de mirar nada más del request.

Header que hay que enviar en cada request:
X-Internal-Api-Key: eYDlzQXNWKOP7H24kp3aGovZ65drRMJCwunB8mLtUhjFxE1g
Ejemplo de cómo se ve un request completo con el header incluido:
POST /wsfe/solicitar-cae HTTP/1.1
Host: api-arca-wsfe.onrender.com
Content-Type: application/json
X-Internal-Api-Key: eYDlzQXNWKOP7H24kp3aGovZ65drRMJCwunB8mLtUhjFxE1g

{
  "token": "...",
  "sign": "...",
  ...
}
Respuesta si falta el header o está mal:
HTTP/1.1 401 Unauthorized

{ "error": "No autorizado" }

Endpoints

GET/health
¿Para qué se usa? Sirve para comprobar que la API está en línea y respondiendo, sin necesitar ninguna credencial. Es el primer endpoint a probar si algo no funciona — si este falla, el problema es que el servidor no está corriendo, no un tema de datos o autenticación.
Headers requeridos:
(ninguno)
Ejemplo de request:
GET /health HTTP/1.1
Host: api-arca-wsfe.onrender.com
Respuesta 200:
{ "status": "ok" }
POST/wsfe/solicitar-cae
¿Para qué se usa? Es el endpoint principal: pide a ARCA que autorice un comprobante nuevo (Factura, Nota de Crédito o Nota de Débito) y devuelva el CAE correspondiente. Reconoce automáticamente el tipo de comprobante a partir del campo tipoComprobante y aplica las validaciones y el armado correctos para cada letra (A, B, C, M, E).
Headers requeridos:
Content-Type: application/json
X-Internal-Api-Key: eYDlzQXNWKOP7H24kp3aGovZ65drRMJCwunB8mLtUhjFxE1g
Body (JSON) — campos comunes a todos los tipos:
CampoTipoDetalle
tokenstringrequerido — Token de WSAA
signstringrequerido — Sign de WSAA
cuitstringrequerido — CUIT del emisor, sin guiones
puntoVentanumberrequerido — punto de venta habilitado en ARCA
tipoComprobantenumberrequerido — código AFIP (1, 6, 11, 19, 51, etc. — ver tabla más abajo)
concepto1 | 2 | 3requerido — 1=Productos 2=Servicios 3=Ambos
docTiponumberrequerido — 80=CUIT 96=DNI 99=Consumidor Final
docNrostringrequerido — número de documento del receptor
condicionIvaReceptorIdnumberrequerido — condición frente al IVA del receptor
fechastringrequerido — formato YYYYMMDD
importeTotalnumberrequerido
importeNetonumberrequerido
importeIvanumberopcional
Campos adicionales, obligatorios solo según el tipo de comprobante:
CasoCampos que se vuelven obligatorios
Concepto 2 (Servicios) o 3 (Ambos)fchServDesde, fchServHasta, fchVtoPago (formato YYYYMMDD)
Factura A o M (discriminan IVA)alicuotasIva: array de { id, baseImp, importe }
Nota de Crédito o Nota de Débito (cualquier letra)comprobantesAsociados: array de { tipo, puntoVenta, numero }
Comprobante de Exportación (tipo E)monedaId, monedaCotizacion, paisDestino, y opcionalmente permisosEmbarque
Ejemplo de request completo — Factura C (la más simple, sin discriminar IVA):
POST /wsfe/solicitar-cae HTTP/1.1
Host: api-arca-wsfe.onrender.com
Content-Type: application/json
X-Internal-Api-Key: eYDlzQXNWKOP7H24kp3aGovZ65drRMJCwunB8mLtUhjFxE1g

{
  "token": "PD94bWwgdmVyc2lvbj0iMS4wIiBlbmNvZGluZz0i...",
  "sign": "Tz9ZH2vQpL8mR3xK1nJ7wA4bC6dE9fG0hI5jK2lM8nO...",
  "cuit": "20111111112",
  "puntoVenta": 1,
  "tipoComprobante": 11,
  "concepto": 1,
  "docTipo": 96,
  "docNro": "12345678",
  "condicionIvaReceptorId": 5,
  "fecha": "20260902",
  "importeTotal": 1210,
  "importeNeto": 1000
}
Respuesta 200 — comprobante aprobado por ARCA:
{
  "exito": true,
  "cae": "71234567890123",
  "caeVencimiento": "20260912",
  "numeroComprobante": 45
}
Respuesta 200 con exito:false — ARCA rechazó el comprobante:
{
  "exito": false,
  "numeroComprobante": 45,
  "errores": [
    { "codigo": "10016", "mensaje": "CUIT representado no incluido en Token" }
  ]
}
Respuesta 400 — falta un campo o el body está mal formado:
{
  "exito": false,
  "errores": [
    { "codigo": "VALIDACION", "mensaje": "token: Required" },
    { "codigo": "VALIDACION", "mensaje": "alicuotasIva: Este tipo de comprobante requiere discriminar IVA (alicuotasIva)" }
  ]
}
Respuesta 401 — falta el header o la key es incorrecta:
{ "error": "No autorizado" }
Respuesta 429 — se superó el límite de solicitudes para ese CUIT:
{
  "exito": false,
  "errores": [
    { "codigo": "RATE_LIMIT", "mensaje": "Demasiadas solicitudes, intentá de nuevo en un momento" }
  ]
}
Respuesta 500 — error de conexión con ARCA o excepción interna:
{
  "exito": false,
  "errores": [
    { "codigo": "ERROR_INTERNO", "mensaje": "descripción del error" }
  ]
}
GET/wsfe/ultimo-comprobante
¿Para qué se usa? Permite averiguar cuál sería el próximo número de comprobante a emitir para un punto de venta y tipo de comprobante determinados, sin emitir nada todavía. Útil, por ejemplo, para mostrarle al usuario "tu próxima factura va a ser la N° 46" antes de que confirme la operación.
Headers requeridos:
X-Internal-Api-Key: eYDlzQXNWKOP7H24kp3aGovZ65drRMJCwunB8mLtUhjFxE1g
Query params (todos requeridos):
ParámetroTipoDetalle
tokenstringToken de WSAA
signstringSign de WSAA
cuitstringCUIT del emisor
puntoVentanumberPunto de venta a consultar
tipoComprobantenumberCódigo AFIP del tipo de comprobante
Ejemplo de request completo, con datos de ejemplo (mock):
GET /wsfe/ultimo-comprobante?token=PD94bWwgdmVyc2lvbj0iMS4wIi...&sign=Tz9ZH2vQpL8mR3xK1nJ7wA4bC6dE9fG0h...&cuit=20111111112&puntoVenta=1&tipoComprobante=11 HTTP/1.1
Host: api-arca-wsfe.onrender.com
X-Internal-Api-Key: eYDlzQXNWKOP7H24kp3aGovZ65drRMJCwunB8mLtUhjFxE1g
Ejemplo equivalente con curl:
curl "https://api-arca-wsfe.onrender.com/wsfe/ultimo-comprobante?token=PD94bWwgdmVyc2lvbj0iMS4wIi...&sign=Tz9ZH2vQpL8mR3xK1nJ7wA4bC6dE9fG0h...&cuit=20111111112&puntoVenta=1&tipoComprobante=11" \
  -H "X-Internal-Api-Key: eYDlzQXNWKOP7H24kp3aGovZ65drRMJCwunB8mLtUhjFxE1g"
Respuesta 200:
{
  "exito": true,
  "proximoNumero": 46
}
Respuesta 400 — faltan parámetros en la query:
{
  "exito": false,
  "errores": [
    { "codigo": "VALIDACION", "mensaje": "Faltan parámetros: token, sign, cuit, puntoVenta, tipoComprobante" }
  ]
}
POST/admin/reset-soap-client
¿Para qué se usa? Es un endpoint de mantenimiento, no de negocio. Fuerza a la API a descartar la conexión SOAP que tiene cacheada contra ARCA y a reconstruirla en la próxima llamada (vuelve a descargar el WSDL). Se usa si la conexión con ARCA queda en un estado raro y no se quiere reiniciar todo el servidor.
Headers requeridos:
X-Internal-Api-Key: eYDlzQXNWKOP7H24kp3aGovZ65drRMJCwunB8mLtUhjFxE1g
Body:
(no requiere body)
Ejemplo de request:
POST /admin/reset-soap-client HTTP/1.1
Host: api-arca-wsfe.onrender.com
X-Internal-Api-Key: eYDlzQXNWKOP7H24kp3aGovZ65drRMJCwunB8mLtUhjFxE1g
Respuesta 200:
{
  "exito": true,
  "mensaje": "Cliente SOAP reiniciado"
}

Códigos de error propios de esta API

CódigoHTTPSignificado
VALIDACION400Falta un campo o el body/query no cumple el formato esperado
RATE_LIMIT429Se superó el límite de solicitudes permitidas para ese CUIT en la ventana de tiempo configurada
NOT_FOUND404La ruta solicitada no existe en esta API
ERROR_INTERNO500Error de conexión con ARCA, timeout, o excepción no controlada

Cuando ARCA rechaza un comprobante (no es un error de esta API, sino un rechazo real), el código y mensaje que aparecen en errores son los que devuelve ARCA tal cual, ya que dependen de la causa puntual del rechazo.
